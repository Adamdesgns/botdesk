# BotDoor PC viewing without editing — local build, 2026-09-29

Adam said the bot may close windows but must not erase anything. A bot with unrestricted clicks and typing can delete through ordinary app controls even when the Delete key and file APIs are blocked. This build therefore makes PC-wide access an observation and navigation mode: capture, inspect, list, focus, move the pointer, scroll, and close the focused ordinary window with Alt+F4. It rejects click, drag, type, clipboard access, and all other keys in PC-wide mode. One-window mode retains its existing editing controls.

The JavaScript guard and Windows native helper both reject PC-wide editing. Owner and MCP text state the restriction. Saving access rules still stops access and cancels schedules; GO LIVE remains separate. The deployed 1.4 host and relay remain on the earlier release, selected-window mode, access OFF. This 1.5 source is local only until approved for deployment.

Closing an app may discard unsaved work or trigger an app-specific prompt. Browser navigation, focus, and scrolling are not a Windows read-only sandbox, and no software can guarantee every app has no side effects. The reliable claim is that BotDoor does not deliver PC-wide click, typing, drag, clipboard, or editing-key commands in this build. Do not describe it as deletion-proof.

Local verification: `npm run check` passed the full tests, relay types and 18-tool MCP smoke. The native fake-window test rejects click, type and Delete before any real window can be resolved. `node scripts/phone-dashboard-smoke.mjs` passed at 390 px and 320 px with a synthetic loopback owner API; the 320 px screenshot is `evidence/phone-pc-access-320.png`. The old 1.4 host was restarted after it exited; authenticated owner status returned PC online, OFF, selected-window, no schedule.
